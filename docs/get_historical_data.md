# `get_historical_data(symbol, n, timeframe="1D")`

คืนแท่งราคา (OHLCV) ของ `symbol` ย้อนหลัง **`n` sequence** — จากช่วงเวลา**ก่อนวันที่กำลังแข่งขัน/จำลองอยู่เท่านั้น**
ไม่มีทางเห็นข้อมูลของวันนั้นเอง หรือวันหลังจากนั้นเด็ดขาด แม้ไฟล์ของวันเหล่านั้นจะมีอยู่บนเครื่องแล้วก็ตาม

## เรียกใช้งาน

```python
bars = self.handler.get_historical_data("AOT", 5)                     # แท่งรายวัน 5 แท่ง
bars = self.handler.get_historical_data("AOT", 100, timeframe="5min") # แท่ง 5 นาที 100 แท่ง
```

## `timeframe` — แท่งรายวัน หรือแท่งระหว่างวัน (intraday)

ไม่ใส่ = `"1D"` (แท่งรายวัน) เหมือนเดิมทุกอย่าง ถ้าใส่ต้องเป็นค่าใดค่าหนึ่งนี้:

`"1min"` `"3min"` `"5min"` `"10min"` `"15min"` `"30min"` `"60min"` `"120min"` `"240min"` `"1D"`

- เขียนแบบอื่นที่ยาวเท่ากันได้ เช่น `"1h"` = `"60min"`, `"4h"` = `"240min"` — ใส่ค่าเดียวกับที่ส่งให้
  `super().__init__()` ได้เลยถ้าเป็นหนึ่งในนี้
- ค่าอื่น เช่น `"2min"`, `"45min"`, `"1W"` → **error ทันที** (`ValueError` บอกรายชื่อค่าที่ใช้ได้) ผลตรวจ (CI) จับได้ตั้งแต่ตอน push
- แท่ง intraday มี field **`"Timestamp"`** (วันที่ + เวลาเริ่มแท่ง) แทน `"Date"` — หน้าตาเดียวกับ `bar` ใน `on_data`:
  ```python
  {"Timestamp": "2026-09-16 09:45:00", "Open": 60.75, "High": 61.25, "Low": 60.75, "Close": 61.0, "Volume": 743200}
  ```
- กัน lookahead แบบเดียวกัน: ได้แค่แท่งของ**วันก่อนหน้า** ไม่มีแท่งของวันที่กำลังเทรด (แท่งของวันนี้ได้จาก `on_data` อยู่แล้ว)
- `n` นับเป็น**จำนวนแท่ง** สูงสุด 1000 เหมือนรายวัน

**ข้อมูล intraday มีย้อนหลังไม่ยาวเท่ารายวัน** — แหล่งข้อมูล (Settrade) เก็บแท่งสั้น ๆ ไว้ไม่กี่วัน ผู้จัดเริ่มเก็บสะสม
ตั้งแต่ 2026-09-29 และเพิ่มให้ทุกวันทำการ ณ วันที่เริ่มเก็บ มีประมาณนี้ (หุ้นส่วนใหญ่):

| timeframe | ย้อนไปถึง | จำนวนแท่ง |
|---|---|---|
| `1min` | 2026-09-24 | ~700 |
| `3min` | 2026-09-23 | ~400 |
| `5min` | 2026-09-21 | ~380 |
| `10min` | 2026-09-14 | ~360 |
| `15min` | 2026-09-07 | ~370 |
| `30min` | 2026-08-17 | ~400 |
| `60min` | 2026-07-01 | ~490 |
| `120min` | 2026-03-27 | ~480 |
| `240min` | 2025-09-30 | ~480 |

ขอ `n` เกินที่มี → ได้เท่าที่มี ไม่ error เช็ค `len(bars)` ก่อนคำนวณทุกครั้ง โดยเฉพาะ timeframe สั้น ๆ ช่วงต้นการแข่ง

> **แท่งย้อนหลังกับแท่งใน `on_data` มาจากข้อมูลแบบเดียวกัน** — ทั้งสองแหล่งไม่นับหุ้นเศษ (odd lot)
> ตั้งแต่ zip 0.2.3 ไฟล์ tick ตัดรายการหุ้นเศษออกแล้ว แท่งที่ `on_data` สร้างระหว่างวันจึงตรงกับแท่งย้อนหลังของวันเดียวกัน
> และ order จะไม่ถูก match กับราคาหุ้นเศษที่โดดจากกระดานหลัก (zip 0.2.2 ลงไปยังมีหุ้นเศษใน tick — โหลดตัวใหม่)

## `n` = จำนวน sequence ที่ต้องการ (เลือกเองได้ สูงสุด 1000)

`n` ไม่ใช่การนับเป็น "วัน" — คือจำนวน **sequence (แท่ง OHLCV)** สูงสุดที่ต้องการโดยตรง แต่ละ sequence สร้างมาจาก
tick ของวันทำการหนึ่งวัน (รวม tick ทั้งหมดของวันนั้นให้เหลือ 1 แท่ง Open/High/Low/Close/Volume) โดยระบบจะไล่หา
sequence ล่าสุดที่มีอยู่จริงย้อนหลังไปเรื่อยๆ จนกว่าจะได้ครบ `n` sequence หรือหมดข้อมูลก่อน:
- ขอ `n` sequence แต่ข้อมูลย้อนหลังมีไม่พอ → ได้เท่าที่มีจริง ไม่ error
- ขอ `n` เกิน **1000** → ถูก cap ให้อัตโนมัติที่ **1000 sequence สูงสุดต่อการเรียก 1 ครั้ง** ไม่ error

## รูปแบบข้อมูลที่ได้กลับมา

`list` ของ `dict` เรียง**จาก sequence เก่าไปใหม่** (ascending) ยาวไม่เกิน `min(n, 1000)` รายการ:

```python
[
    {"Date": "2025-11-17", "Open": 30.00, "High": 30.50, "Low": 29.75, "Close": 30.25, "Volume": 1234500},
    {"Date": "2025-11-18", "Open": 30.25, "High": 30.75, "Low": 30.00, "Close": 30.50, "Volume": 987000},
    ...
]
```

## ตัวอย่างจริง เทียบ `n` กับจำนวน sequence ที่ได้

สมมติกำลังแข่งขัน/จำลองอยู่ที่ sequence ปัจจุบัน (เรียกว่า `D`) และมี sequence ย้อนหลังที่มีข้อมูลจริงต่อเนื่องกัน 5 sequence ก่อนหน้า `D`:

`... [sequence -5] [sequence -4] [sequence -3] [sequence -2] [sequence -1] [D — ห้ามเห็น]`

เรียก `get_historical_data("AOT", n)` จากภายใน strategy ที่กำลังรันอยู่ที่ `D` จะได้:

| `n` ที่เรียก | จำนวน sequence ที่ได้กลับมา | ตัวไหนบ้าง (เก่า→ใหม่) |
|---|---|---|
| `1` | 1 sequence | `[sequence -1]` — sequence ล่าสุด**ก่อน** `D` เท่านั้น |
| `3` | 3 sequence | `[sequence -3, sequence -2, sequence -1]` |
| `5` | 5 sequence | `[sequence -5, sequence -4, sequence -3, sequence -2, sequence -1]` — พอดีทุก sequence ที่มีอยู่ |
| `10` | 5 sequence | เหมือนแถว `n=5` — ขอ 10 แต่มีข้อมูลจริงแค่ 5 sequence ก่อนหน้า → **ได้เท่าที่มีจริง ไม่ error** |
| `5000` | สูงสุด 1000 sequence | ขอเกิน 1000 → **ถูก cap ที่ 1000 sequence อัตโนมัติ ไม่ error** |
| `0` หรือค่าติดลบ | 0 sequence | `[]` (list ว่าง) |

**ข้อควรระวัง**
- ถ้า sequence ไหน `symbol` ที่ถามไม่มีการซื้อขายเลย sequence นั้นจะถูก**ข้ามไป** ไม่ได้ใส่แท่งราคาว่างๆ (0) มาแทน ดังนั้นจำนวน sequence ที่ได้จริงอาจน้อยกว่า `n` ที่ขอ ถ้า symbol นั้นหยุดซื้อขายบาง sequence ในช่วงที่ขอย้อนหลัง
- ห้ามคาดหวังว่าจะเห็น sequence ของช่วงที่กำลังแข่งขันอยู่เอง (`D`) ไม่ว่าจะเรียก `n` เท่าไหร่ก็ตาม — เป็นการป้องกัน lookahead ตามกติกาการแข่งขัน
- เลือกจำนวน sequence ที่จะเอาได้เองผ่าน `n` โดยตรง (ไม่ต้องขอมาเกินแล้วมาตัดเอง) แต่**สูงสุดคือ 1000 sequence ต่อการเรียก 1 ครั้ง**

**อาจได้ sequence ย้อนไกลกว่าช่วงการแข่งขันเองด้วย** — ถ้าผู้จัดเตรียมข้อมูลย้อนหลังเพิ่มไว้ให้ (นอกเหนือจากข้อมูล tick
ของช่วงแข่งขันเอง) `n` ที่ขอสูงๆ อาจได้ sequence ย้อนไปไกลกว่าที่คิดไว้ — ไม่กระทบวิธีเรียกใช้หรือ format ข้อมูลที่ได้
เลย แค่ให้รู้ไว้เฉยๆ ว่าทำไมบางทีได้ sequence เยอะกว่าที่คาดตอนแรก

## เรียกใน `__init__` ไม่ใช่ใน `on_data`

`self.handler` ใช้งานได้ตั้งแต่ใน `__init__` ของกลยุทธ์ ซึ่ง**ทำงานครั้งเดียว** ต่างจาก `on_data`
ที่ถูกเรียก**ทุก tick** วันหนึ่งประมาณ **190,000 ครั้ง**

และเพราะข้อมูลที่ได้หยุดอยู่ที่วันก่อนหน้าเสมอ **มันจึงนิ่งตลอดทั้งวัน** การคำนวณ indicator ใหม่
ทุก tick จึงเป็นการหาคำตอบเดิมซ้ำหลายแสนรอบ

```python
class MyTeam(Strategy_template):
    WATCHLIST = ["AOT", "PTT"]

    def __init__(self, handler):
        super().__init__("MyTeam", "MyTeam", handler, timeframe="1D")
        # คำนวณให้จบตรงนี้ ครั้งเดียว
        self.signals = {s: self._decide(s) for s in self.WATCHLIST}

    def _decide(self, symbol):
        history = self.handler.get_historical_data(symbol, 120)
        ...

    def on_data(self, bar):
        signal = self.signals.get(bar["ShareCode"])   # แค่เปิดดูคำตอบ
        ...
```

**ทำไมถึงสำคัญ** — ไม่ใช่เรื่องความเร็วของการดึงข้อมูล (engine cache ไว้ให้แล้ว ดึงใน `on_data`
ก็ได้ผลเท่ากัน) แต่ไฟล์จะแยกชัดเป็น "เตรียมตัว" (`__init__`) กับ "ระหว่างวัน" (`on_data`) และวันที่ใช้
ของหนักจริง เช่นโมเดล ML หรือ optimizer ถ้าเรียกทุก tick จะช้าจริง — รันจริงมีเพดาน **15 นาที/ทีม/วัน**

⚠️ **CI จับเรื่องนี้ไม่ได้** — ตอน CI ไม่มีข้อมูลย้อนหลัง `get_historical_data()` คืน `[]` เสมอ (ทุก timeframe)
โค้ดหลัง `if len(history) < N` จึงไม่ถูกรันใน CI เลย ต้องรันใน `TradingSimulation.ipynb` ให้เห็นผลเอง
(ยกเว้นใส่ `timeframe` ที่ไม่มีข้อมูล อันนั้น error ทันทีแม้ใน CI)

## ขอข้อมูลย้อนหลังของ **ดัชนี SET50** ได้ด้วย

นอกจากหุ้นรายตัว ยังขอแท่งราคาย้อนหลังของตัวดัชนีเองได้ โดยใส่ `"SET50"` เป็น `symbol`:

ใช้ทำอะไรได้ เช่น ดูว่าตลาดโดยรวมเป็นขาขึ้นหรือขาลงก่อนตัดสินใจเข้าซื้อรายตัว, เทียบแรงของหุ้นกับดัชนี
(relative strength), หรือคำนวณ beta/correlation ของ watchlist ตัวเองเทียบตลาด

**ข้อควรรู้ 3 ข้อ**

1. **`on_data` ไม่เคยถูกเรียกด้วย `SET50`** — ข้อมูล tick รายวันมีแต่หุ้นรายตัว (48-50 ตัว) ไม่มีดัชนีอยู่ในนั้น
   ถ้าอยากได้ข้อมูลดัชนีต้องเรียก `get_historical_data("SET50", n)` เองจากใน `on_data` ของหุ้นตัวอื่น
2. **สั่งซื้อขาย `"SET50"` ไม่ได้ — ซื้อได้แค่ "ตัวหุ้น" ที่เป็นองค์ประกอบของดัชนีเท่านั้น**
   ดัชนีเป็นตัวเลขที่คำนวณขึ้นมา ไม่ใช่หลักทรัพย์ที่มีหุ้นให้ถือครอง `create_order_*` จะปฏิเสธด้วยข้อความ:

   > `'SET50' is a market index, not a tradable stock -- orders can only be placed on the individual`
   > `SET50 constituent stocks (AOT, PTT, ...). To read the index itself, use get_historical_data('SET50', n).`

   เช่นเดียวกับ `SET` และชื่อดัชนีอื่น ๆ — **ใช้ดัชนีเพื่อตัดสินใจว่าจะเทรดหุ้นตัวไหน แล้วค่อยสั่งซื้อที่ตัวหุ้นนั้น**
3. **กัน lookahead เหมือนกันทุกประการ** — ไม่มีทางเห็นค่าดัชนีของวันที่กำลังเทรดอยู่ ได้ถึงแค่วันทำการก่อนหน้า
   เช่นเดียวกับหุ้นรายตัว

> ข้อมูลดัชนีชุดนี้เป็นคนละชุดกับที่ผู้จัดใช้คำนวณ Benchmark Return / Excess Return ตอนให้คะแนน —
> กลยุทธ์ไม่มีทางเข้าถึงตัวเลขคะแนนหรือ benchmark ของการแข่งขันได้
